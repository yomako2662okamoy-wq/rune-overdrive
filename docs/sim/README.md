# バランスシミュレーター（6.3）

実行はプロジェクト内で `node tools/sim.mjs`。条件は `tools/sim-config.json` で指定する。ライブラリ追加・ネット接続は不要。

- 標準: 7×6、K=100、各ダンジョン200試行、推奨Lv、初期5人（アカネがリーダー）、全員スキルLv1。途中の経験値でレベルは変えない。
- 1候補は開始位置を含め25マスまでのランダムな隣接経路。斜めとロックの通行規則はゲームと共通。K候補のうち離す直前のコンボ数が最大の経路を採用し、同数なら先に試した候補を選ぶ。将来の落ちコンを先読みしない。暗闇は記憶している色として扱う。
- スキル方針は前後で固定: HP50%以下ならルカの回復、次に攻撃する敵がいるならノクトの遅延。その他のスキルは使わず、ターゲットは通常の先頭優先。
- 計算はすべてindex.htmlのLOGICを使う。候補の乱数は盤面・敵から独立。seedから試行ごとの種を固定し、スレッドの実行順に依存しない。
- 現在は300ターン上限と移動不能を失敗として別集計。最低HPは各回の途中の最低値を測り、CSVにはその平均・平均%・全試行の最小値を出す。平均ターンとODは失敗も含む試行平均、平均コンボは全ターン平均。
- Kは30／100／300、levelsに配列を指定するとダンジョン×レベルの表になる。省略時は推奨Lv。
- before.csvとafter.csvは同じ種・試行数で比較。これはボット条件での測定で、実際の人の勝率ではない。

Baseline source: 62c8e3e. Tuned enemy data: df0f777. Both CSV files use seed 20261006, K100, 200 trials per dungeon, maximum 200 turns. The later performance changes preserve LOGIC and DATA.

## C-3追加調整の測り方

- 調整中は `node tools/sim.mjs --runs 50`、最終確認は `node tools/sim.mjs --runs 200`。1試行は300ターンを上限とし、未クリアなら失敗に数える。
- `avgDungeonTurns` は1ダンジョンの全試行の平均ターン数。敗北・300ターン終了も含める。d1〜3は25〜40、d4〜8は30〜50を目標にする。
- 画面には3行の要約だけを出し、ダンジョン別の集計はこのフォルダのCSV・JSONに保存する。smokeの詳細は `tmp/smoke-last.log`（Git管理対象外）。
- 以前のbefore.csv／after.csvは旧ロック規則・200ターン上限での記録。C-3追加調整の比較には、ファイル名が `c3-` で始まる同条件の結果を使う。

## G1（2026-10-10）

- 推奨Lvは `node tools/sim.mjs --runs 200`（結果は `g1-balance-200.csv`）。目標はクリア率が指示書6.3、ターン数がF6（d1 12〜18、d2〜3 16〜24、d4〜8 20〜30）。sim.mjs の表示もF6に合わせた。
- 調整は Claude の作業用スクリプトで行った（コミットしていない）。手順：①敵の攻撃を1倍にしてHPの倍率をフロアごとのターン数（雑魚3〜4、ボス5.5〜9）に合わせる、②ボスの一撃を推奨LvのチームHPに対する割合で決め、雑魚はその0.62倍の「フロアの1ターンあたり」の被ダメージにして、クリア率を見る。
- 寄り道なしで着くLvでの結果は docs/balance-g1.md。
